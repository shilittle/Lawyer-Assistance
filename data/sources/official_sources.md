# Official Legal Data Sources

This project builds the bundled `legal_core.sqlite` from official public sources only.

## National Laws And Regulations Database

- Source: https://flk.npc.gov.cn/
- Maintainer: 全国人大常委会办公厅
- Used for: 宪法及修正案、法律、行政法规、监察法规、地方性法规、自治条例和单行条例、经济特区法规、浦东新区法规、海南自由贸易港法规、司法解释，以及该库公开的历史版本、修改废止决定和相关资料。
- Local source id: `flk_npc`

## National Rules Database

- Source: https://www.gov.cn/zhengce/xxgk/gjgzk/index.htm?searchWord=
- Maintainer: 中国政府网
- Used for: 现行有效部门规章和地方政府规章。
- Local source id: `gjgzk_gov`

## Supreme People's Court Official Website

- Source: https://www.court.gov.cn/
- Maintainer: 最高人民法院
- Used for: “指导案例”栏目逐案例正文及批次通知、“典型案例发布”栏目发布集合、“诉讼文书样式”栏目逐模板正文。
- Snapshot boundary: 2026-07-11; 278 individually published guiding cases, 15 batch notices, 412 typical-case release collections, 597 stable typical-case records derived without leaving their official collection source, and 752 document templates.
- Declared source exception: the official guiding-case listing contains no independent detail page for No. 45; the official tenth-batch notice covering Nos. 45–52 is retained instead. No non-official replacement text is imported.
- Local source id: `spc_court`

## Current Build State

`legal_core.sqlite` is generated by `data/build/build_legal_core.py`.

The current bundled database is a real official-source full-text legal database for the declared Stage 1B scope, not a sample dataset. It records official source coverage in `coverage_audit` and `database_metadata.coverage_report`.

Current strict audit status is `complete`: detail/text hydration, article segmentation, relation expansion, source records, attachments, and ingestion audit rows are present for the declared Stage 1B scope. Stage 1C normalizes official `lsyg` relations into multi-version documents, records every unresolved date family without inventing values, and imports the declared Supreme People's Court guiding-case, typical-case, and document-template website snapshot with complete per-record provenance.

The Stage 1B builder now has resumable `index`, `hydrate`, `assemble`, `audit`, and `all` stages, writes per-record status to `data/build/state/legal_core_jobs.sqlite`, and writes per-record ingestion status to the generated SQLite database's `ingestion_audit` table. A full Stage 1B handoff is valid only when the strict audit reports `coverage_status = complete`.
