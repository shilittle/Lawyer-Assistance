## 阶段 4 实现与专项门禁

默认程序不提供内存/超时故障入口。独立测试 feature 构建的 worker 以 8 MiB 分块 VirtualAlloc，并逐个 4 KiB 页写入；实际在 512 MiB Job 中记录 Win32 1455 分配拒绝，已触碰 528,482,304 bytes，首次拒绝位置 536,870,912 bytes，目标及总尝试 545,259,520 bytes。普通进程退出或缺失报告不能使该断言通过。内存拒绝和注入超时后均验证任务失败、子进程回收、AI/解析许可归零及同一 daemon 下一份扫描 PDF 成功。默认程序拒绝故障命令，传入故障环境变量仍能正常处理 PDF。750 ms 仅用于测试 feature 的 stall，生产渲染预算仍为 90 秒。

取消、worker 崩溃、损坏 PDF 的原生恢复脚本通过 9 项断言。首次恢复夹具重用了之前 PDF 的字节而命中 OCR 缓存，新增“必须调用 OCR”的测试失败；原始日志保留，后以不同源哈希重跑通过。此问题是夹具对缓存的错误假设，不能报告成产品故障。

材料 worker 改为逐任务监督。panic 后可靠写入失败终态，不能覆盖新版本或已取消记录；持久化失败时保持降级并以最多 5 秒的指数退避重试，写入成功前不继续领取下一条。解析许可由任务退出释放。新增 panic、取消竞争、失败终态写入失败及随后恢复的真实 Rust 回归；旧 v2 备份复制到独立目录重新打开和迁移，核对对象完整。该批工作区服务默认单元回归为 97/97。

净化器展开未知容器前递归检查后代，清除嵌套危险节点、事件/样式属性及危险 URL，同时保留安全内容。修前实际 daemon 的 CSP 响应通过但独立 DOM 检查失败，说明 CSP 不能替代 DOM 净化。修后门禁同时检查实际服务页面及脚本的 CSP、同源执行和独立 DOM。

验收器现在为构建产物和原生检查记录实际默认/故障程序 SHA-256；资源来自显式公开库副本，来源清单仍核对提交 LF 原始字节及索引自哈希。缺工具为 blocked、未执行依赖为 not_run；已有尝试不允许覆盖。Windows CI 固定 Rust 1.98、Node 24、pnpm 11.7，动态纳入全部 Python 模块，并接入编辑器、能力/错误目录和范围选择的确定性 Chromium 回归。远端 CI 未执行，不能把配置变更写成云端通过。

交付脚本支持明确基线、日期与提交标签；源码包含相对 df1a000 的补丁，验证包只接收带字节长度和 SHA-256 的显式证据清单，便携包从公开库副本组装。输出重名拒绝覆盖，上一轮交付保留。独立证据原始 ZIP/JSON 仍未取得；原始闪退根因仍未确认。
