## 验收边界对应

| 要求 | 对应验证 |
| --- | --- |
| 纯本地处理，无人工发布批准 | 确定性号码材料从导入自动变成 ready，由实际 MCP 读取替换后的正文 |
| 云授权绑定、撤销及目标变化 | 本机模拟 Provider 验证材料版本、Provider 配置、模型、用途和授权状态；轮询发送前复核和取消共享同一状态锁 |
| 云返回不可信 | 非法 JSON、原文中不存在的候选、疑难候选不直接发布；始终由本地生成替换文本 |
| DOCX 完整性 | 表格提取、附属文本、修订、图片、损坏包、ZIP/XML 攻击回归；不支持内容明确阻断结果 |
| 结果有效性 | 源文件/词典修改、撤销、过期、待复核、失败均不可继续读取旧结果；替换范围及原文/输出哈希重新验证 |
| 任务一致性 | 批量部分失败、重复 ID、取消/重试、重启恢复、并发修改、MCP 超时后的并发占用回归 |
| 文件边界 | 相对路径、父目录身份、junction/reparse point、源文件打开及变化检查 |
| 对话边界 | 显式上下文、历史结果撤销、流取消/断线/截断、分块凭据回显拦截；无自主工具执行 |
| 导出 | 仅 ready 材料入包，逐项报告其余状态；TXT/Markdown/重建 DOCX 再打开验证 |
| 公开法律 MCP | 保留工具与参数契约，独立进程不打开私密工作区 |

MCP 沿用 [2025-11-25 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)，实际分别验证 HTTP 与逐行 JSON-RPC stdio。此处不宣称运行了外部认证套件。
