# V1.2.0 AI 增量验收报告

记录环境为 Windows x86_64 / MSVC，验收日期为 2026-09-09 至 2026-09-10。本报告记录本机实测，不代表远端 CI 或 GitHub 发布。源码保留 V1.0.0 及实施前未提交的案例检索增量。

本报告分别记录功能验证、自动完成结果、失败与人工复核事项；不将后两者算作自动通过。逐项机器证据另附验收 ZIP。

## 验收材料与独立性

独立子代理在不读取脱敏规则的前提下生成 12 组虚构案情、62 份材料；另一子代理独立标注实体、日期、金额、事实锚点和视觉转录。覆盖买卖、劳动、租赁、公司、教育等争议，同名当事人、表格、内嵌图片、扫描件、模糊图、长文、伪造指令与损坏文件；C03、C07、C10、C12 保留为盲测组。正常材料 60 份，故意损坏的 DOCX、PDF 各 1 份。

格式包括 UTF-8/GB18030 TXT、带表格和图片的 DOCX、文本层 PDF、扫描 PDF、PNG、JPEG、WebP。文件哈希与标注逐份绑定，不能以处理其他版本或仅检查分析对象代替导出检查。自动完成的材料必须有可读 TXT，比较实体残留和非目标事实；待复核、失败、缺少导出分别计数，不计入通过。引号和空白等格式等价转换单独记录。

材料清单、独立标注和原始日志位于本机 `output/ai-upgrade-fixtures`、`output/ai-upgrade-annotation`，不进入产品包。测试指标只描述这组虚构材料，不外推为真实案件准确率。

## 实际 GLM 调用

使用用户提供的密钥，调用智谱官方地址 `https://open.bigmodel.cn/api/paas/v4`，模型 `glm-5.3-flash`，`reasoning_effort=low`。密钥不写入报告或包内。设置实际获取模型列表并保存多模型启用和四种用途配置；鉴权失败如实显示，不用预设名单替代联网响应。

初期能力探测完成文本、工具结果回传和图片识别，供应商报告 833 tokens。完整业务验收另行计数。已有供应商列表探测中通义千问返回 401，其余四个已提供供应商成功；这不代表通义服务不可用，只表明该次凭据请求失败。

AI 搜索、文书写作、AI 会话各执行三次复杂买卖争议：126800 元货款、已付 30000 元、余款 96800 元，包含质量异议、代理权限、付款损失和举证争点。首批九次完成后，根据独立语义审查增加正文法名与条号核验、事实与推断区分，再完整重复九次。

最后一批搜索三次引用数为 6、7、12，工具调用数为 24、20、23；写作最终引用数为 6、9、7，工具调用数为 15、22、16；会话引用数为 8、7、8，工具调用数为 23、20、19。工具次数包含同一任务继续后的已保存步骤。达到每段预算时保存为暂停，继续后完成；第三次写作初次因 `citation_quote_mismatch` 被拦截，继续两轮后修正并完成。首轮失败率 1/9，最终九份结果均完成，原失败与暂停记录保留。

独立审查的 70 个法条引用、25 个唯一 ID 均通过法名、版本、原文和逐字 quote 核验；无无效 ID、缺 quote、引文不匹配或正文条号未配对。金额、主体及付款事实无直接错误。但仍有 6 项法律表述需要人工复核，包括质量抗辩条件写得过强、起算日标签或前后表述不一致，以及第五百八十三条的适用条件遗漏。工具引用真实不能替代法律分析质量验收；本版生成文书仍须逐项复核事实与适用条件。详见 `output/ai-upgrade-semantic-final/manual-assessment.md`。

历史读取、继续任务、材料撤销、供应商配置变化、显式取消和手动标题保护另由确定性回归验证。最终调用用量以后台 `ai_dispatch` 记录汇总，避免把继续任务的累计用量与原任务重复相加。

## 脱敏问题发现与复测

首轮 62 份实测曾得到 15 份 ready、29 份 needs_review、18 份 failed；15 个可读导出中 13 个通过盲标比较，2 个存在真实项目编号残留。该轮未达到验收要求，保留原始报告。

独立诊断确认的问题包括：旧二进制没有 WebP 分支；本地 NER 把整句识别为组织，和 AI 精确实体重叠后导致全局复核；普通重复实体漏覆盖；金额、日期被错误当作 custom 候选；OCR 或实体 JSON 响应不完整。同名不同身份需要复核，与上述程序问题分别处理。

已补充 WebP 校验和有界 PNG 转换、实体重叠处理、重复实体覆盖、结构化编号检测及针对性回归。后续全量得到 39 份 ready、8 份待复核、15 份失败；显式重试可重试的云请求后得到 40 份 ready、9 份待复核、13 份失败。两轮所有 ready TXT 均可读取，均未发现已标注敏感实体残留。没有关闭残留检查、改写盲标或把复核状态算作成功。

重试后的 40 份导出中，自动金标比较为 35 份通过、5 份比较不一致。独立逐页核对后，5 份均属于标注或比较范围问题：C03 的“具体值不可见”是标注说明；C03 WebP 和 C11 JPEG 只有首张源图，而金标引用了后续 PDF 页面的事实；C03/C11 DOCX 的金额记录位于表格，不能按连续句子匹配。可见的金额和日期保留完整，未发现实际事实丢失。报告保留自动结果，不把人工解释改写成自动严格全通过。

定位响应失败后，修正了重复实体的唯一上下文定位与重试反馈；上下文必须保留原文换行，不能猜测。最终复测得到 **41 份 ready、11 份待复核、10 份失败**。41 份导出均可读取且无已标注敏感实体残留；自动金标 36 份通过，另 5 份仍为上述已独立核对的标注范围或表格比较差异。10 份失败为 8 份 OCR 遮挡或不完整和 2 份故意损坏文件，实体 JSON 解析失败已清零。

待复核包括同名不同当事人及模型对案例标签、页边伪造指令等 custom 候选的歧义。它们不提供自动完成导出。本轮没有达到“全部正常样本自动完成”的要求。C01 五格式关键流程前两轮全部 ready，第三轮经重试为 4 份 ready、1 份待复核，表明模型判断仍有波动。独立证据见本机 `output/ai-upgrade-redaction-validation/final-independent-diagnostic.md`；最终逐份状态及金标比较见 `output/ai-upgrade-redaction-release`。

最终状态审查还修复了人工复核丢失 AI 专属实体的问题。分析对象持久化已核验的 AI 片段和位置，并区分合法空集与旧版缺失记录。复核前核对原件哈希，保留 AI 候选再应用人工字典；字典变更使其他材料记录失效时要求重新处理。同名歧义、低置信候选仍需明确确认，旧版纯本地结果继续兼容。11 项专门回归覆盖这些状态变化。

## 完整法律检索与最高法案例

原法律库保持不变：34549 部法律、40293 个版本、1181655 条条文。原始 SQLite SHA-256 为 `86574bba91950b194c6530586eebbae31c689a5bd2a485877b3eed6b611f7d3c`。派生索引与原库分离，索引仅加速候选召回，完整匹配集统一计算排序、筛选和分页。

真实库“公司”逐条结果为 7625 条、归组结果为 2861 部；“合同”逐条 39200 条、归组 10547 部。分页遍历核对无重复、无遗漏。第二页在进程缓存下分别约 11/59 毫秒，归组约 3/14 毫秒；首次查询约 9–23 秒，不把缓存耗时冒充首次查询性能。历史版本已验证能读实际条文。

用户提供的 `最高法案例_TXT资料包_20260909.zip` SHA-256 为 `4a44fa427be3ed71b3d457cdaac6d96f38fb23a31c8f68553e8ddba2f7c5dc44`。逐项核对 834 个来源 TXT 哈希，合并为 759 条主案例或合集：279 指导、61 参考、419 典型合集。不同来源版本保留；撤销通知不冒充独立案件；典型合集可能包含多个案件。

HTTP、浏览器与公开 MCP 已验证指导案例 45、279 以及最大典型合集全文。最大典型合集为 213294 UTF-8 字节、74665 字符，接口返回完整正文。指导案例 45 保留资料包中的洛阳中院官方转载入口。案例库缺失时仍如实返回不可用。

## 文书排版与导出

三份实际生成文书及 80 行跨页表格修改版通过共同解析结构导出 TXT、DOCX、PDF。导出前后后台调用记录相同，证明导出不会再生成另一份正文。

DOCX 使用本机 Word COM 只读回转 PDF，以核验真实标题、列表和表格；Typst PDF 使用包内思源宋体。三份文书各有 2 页 Typst PDF 和 2 页 Word 回转 PDF，长表格分别为 5 页和 6 页，共逐页检查 23 页。TXT 与 DOCX 提取正文一致，日期金额回读通过；80 行表格全部存在，跨页重复表头，未见裁切、遮挡或中文字形缺失。HTML 注入样例以普通文字显示。

标准技能渲染脚本因本机未安装 LibreOffice 无法使用，改用现有 Word 的只读导出；未把工具不可用描述为运行成功。

最后一批三份文书再次导出并回读，普通 PDF 与 Word 回转 PDF 合计 16 页。独立检查发现 DOCX 页码缺失与一个三级标题孤立，已补充标准 PAGE 页脚和三级标题 keepNext；重新导出不调用模型，所有日期金额与保存正文一致。

## 浏览器与回归

实际 Chromium 在 1366×768、1920×1080、720×900 下完成设置、模型发现、法律/案例搜索、AI 搜索、文书历史预览和 PDF 导出、会话自动标题和手动改名等检查。首批 205 项通过、0 控制台错误；最终视口专项 195 项通过、0 控制台错误，覆盖 12 次搜索、3 次动态窗口变更、9 张截图。法律组使用简洁标题卡片，展开后才读取命中条文；改变窗口高度保留原浏览位置。

HTTP 与 MCP 回归保持公开 7 工具、私密工作区 10 工具；覆盖 stdio、HTTP、导入、幂等重放、状态、读取、权限隔离、后台离线及 token 撤销。新增 AI 流程回归覆盖断流、超时、429、非法 JSON、截断响应、虚构引用、取消晚到响应、材料撤销和原件替换、供应商绑定、暂停继续及备份异常。

最终 Rust 全工作区 **853 项通过**，13 项依赖真实法库或 Pdfium 的检查另行执行并全部通过；Clippy 全工作区全目标和 rustfmt 通过。前端 17 项通过，Python 打包、案例构建、资料包导入、合成 Web 测试库共 19 项通过。

完整并发回归发现两个测试/并发边界问题并保留了诊断：数据库迁移测试原本用任意两秒限制重建，现在以实际遇到写锁为同步证据；Windows 凭据工作流在并行读写/删除下偶发缺失读取，现在读取可并行、写入和删除与读取排他。独立原生 CredMan 压测没有普遍复现，因此不把该现象概括为 Windows API 不支持多线程。AI 工作流及工作区安全测试各连续三轮并发通过后，再完成上述全工作区检查。
