# Lawyer Assistance 1.2.1 修复候选版：逐项修复与验收报告

本地候选版以 `cb085ba753daf39c0cde5a26a492d04ac1db270b` 为基线，修复 LA-01～LA-15，并补齐 zune 许可证正文。保留 WebUI、本地服务、加密工作区和 MCP v1 架构。代码位于 `codex/review-1.2.1` 分支；便携包尚未作为 GitHub Release 发布，程序未签名。

## 最终回归

- Rust 1.98.0：全工作区、所有目标及特性 **943 项通过**；另行执行原生 Pdfium 1 项及正式法规库 12 项，原先忽略的 **13 项全部通过**。Clippy `-D warnings`、格式检查通过。
- 前端 **29 项**、Python 四组 **19 项**通过。基线分别为前端 17/17、Python 18/19。
- Chromium 状态/轮询 **7 项**；真实 daemon 文书/草稿/导出 **5 项**；检索契约 **8 项**；检索容量 **4 项**；AI 容量 **3 项**；完整库索引等价 **10 项**；原生 PDF worker **7 项**；上下文/引用 **13 项**（含 2 项真实浏览器检查）通过。
- 模型仅使用 localhost 合成 mock。检查了实际外发消息的材料依赖与取消连接；没有保存原始模型消息。TXT、原生 Typst PDF 和 DOCX 均从同一保存版本导出，不重新生成。
- 本轮检索取消收尾 8 ms，AI HTTP 取消收尾 39 ms；这些是本机本次测量，不是平台时延承诺。
- 便携包：已通过：归档与逐文件校验、实际随包 Web/Chromium、MCP HTTP/stdio/撤销、PDF worker 和文书导出。

完整命令和退出码位于证据包的 `final-command-results.json` 与 `final-*.log`，可用 `python scripts/audit_validate.py` 重跑。所有门禁失败都会停止后续执行。

## 完整法规库分页性能

数据集 `2026.07.14-stage1c.2` / `runtime-slim-v1`，34,549 部法律、40,293 个版本、1,181,655 篇条文。主库 1,775,419,392 字节，索引 1,994,698,752 字节。使用最终 release 程序实际 `/api/v1/legal/search/page`，5 个查询 × 2 个视图 × 10 次，共 100 次；测量时没有并行编译。

| 测量 | 样本 | p50 / ms | p95 / ms |
| --- | ---: | ---: | ---: |
| 首次查询键 | 10 | 3912.54 | 7710.89 |
| 重复热页 | 80 | 6.47 | 144.91 |
| 首次另一页 | 10 | 3607.39 | 3941.80 |

“首次查询键”指首次请求查询/视图/页键，**没有清空操作系统文件缓存**；另一视图可能复用精确计数。热页重复 offset 0，首次另一页请求 offset 20。样本规模有限，不是持续负载基准。

峰值 RSS **53,600,256 字节**，末态 RSS **19,169,280 字节**；缓存峰值 **619,045 字节**。样本最大候选数 277，最大缓存锁等待 0 ms，报告降级标志的请求 60/100。每个样本保留数量、候选、降级、锁等待、缓存及 RSS；断言两视图和全部页面共享准确计数、缓存不超预算，新页复用精确计数。

第二阶段无并行编译的记录作为过程证据保留（冷键 p95 6050.09 ms，峰值 RSS 62,148,608 字节）。旧实现曾通过完整物化结果获得更快的后续翻页，不能据此代替受预算约束的数据库分页验收，也不能宣称所有性能指标均加速。

## 失败迭代与未确认事项

- 第一轮候选完整库基准发现 flat/grouped 候选语义不一致。`candidate_stage2/report.json` 的旧 `passed` 只表示请求成功，**该轮不构成正确性或性能通过**；修复后增加跨视图精确总数断言并重跑。
- 最终复核重新打开并修复了有限离线退避、实际上下文哈希/历史账目、大视觉预检执行，以及来源库不可用时的聚合错误分类。相关回归已纳入最终门禁。
- 初期硬链接副本触发已有文件安全检查、浏览器断言和旧会话请求字段不匹配属于验收脚本问题；已改为独立副本及新契约，没有将这些失败归因为产品崩溃。
- 未取得原始 Windows 主进程闪退的原生崩溃证据，不能宣称已锁定或完全消除其根因。现有故障注入证明本次 PDF 子进程崩溃不会带走主服务。512 MiB 限额已在真实 Job 上设置并读回，**没有进行实际内存超额分配的故障注入**。
- 大视觉材料当前只接受预算内的完整视觉范围，界面尚无页范围选择器；超限时先拆分或减少文件，或配置有足够容量的模型。模型容量配置未经服务端实测时仍需用户核实。
- 实际法律适用、论证相关性、真实模型生成质量及真实文书最终版式待人工复核。引用机械通过不能替代这些判断。
