# 脱敏合成回归语料与质量报告

`crates/privacy-text/tests/fixtures/redaction-regression-synthetic-v1.json` 是首版的独立合成标注语料。全部姓名、机构、地址、号码和上下文均为虚构测试值；文件不含案件材料、用户材料或真实云端响应。

该语料用于防止规则、词典、NER 协同和复核状态在重构时回退。它不是生产语料，也不是对真实法律材料准确率的估计。

## 覆盖范围

| 范围 | 正样例 | 合理负样例或待复核样例 | 预期处理 |
| --- | --- | --- | --- |
| 中文姓名与跨段稳定别名 | 同一姓名在两个段落中出现两次 | 无云佐证的姓名 NER 候选 | 词典的两次替换必须使用同一别名；单独 NER 进入待复核 |
| 机构 | 词典中确认的公司名称 | 法律文本中的通用机构称谓 | 已确认词典自动替换；通用称谓不得报为实体 |
| 地址 | 词典中确认的中文送达地址 | 只有“送达地址”字段名而没有地址值 | 已确认词典自动替换；字段标签不得报为地址 |
| 数字标识 | 身份证号和手机号码 | 日期和法条条号 | 明确规则自动替换；日期和条号不得报为敏感标识 |
| 混淆字符 | 含零宽字符和全角字形的姓名，附精确云候选 | 无云候选的同一姓名 NER 基线 | 只有本地 NER 与精确原文云候选一致时自动替换；否则待复核 |

词典样例刻意单列：它们证明人工确认后的本地替换和跨文档稳定别名，不用于衡量自动识别器本身。云样例只使用固定的合成候选，证明“本地 NER + 精确云佐证”这条状态机，不调用真实 Provider。

## 可复算报告

在工作区根目录运行：

```powershell
cargo test -j1 -p privacy-text --test synthetic_quality -- --nocapture
```

测试读取固定 JSON，并输出一行 `privacy_text_synthetic_regression`。它报告：

| 字段 | 定义 |
| --- | --- |
| `expected_entities` / `observed_entities` | 按“原文精确片段 + 规范实体类别”计数的标注与检测实体出现次数 |
| `true_positive` | 上述键和出现次数均相符的最小计数 |
| `false_positive` | 观测数减去匹配数；包含负样例中出现的错误实体 |
| `false_negative` | 标注数减去匹配数；包含未发现的标注实体 |
| `automatic_ready_rate_ppm` | 所有语料项中 `needs_review=false` 的比例，包含无敏感信息的干净负样例 |
| `positive_automatic_ready_rate_ppm` | 含标注实体的语料项中可直接发布的比例；其中包含人工词典覆盖，不能解释为纯模型自动通过率 |
| `pending_rate_ppm` | 所有语料项中仍需复核的比例 |
| `automatic_deterministic` | 实际由确定性规则替换的实体出现次数 |
| `automatic_dictionary_manual_coverage` | 实际由已确认词典覆盖的实体出现次数 |
| `automatic_cloud_ner` | 实际同时有本地 NER 和精确云候选佐证后替换的实体出现次数 |

测试会在该固定语料上断言漏检和误报均为零，并验证每个样例的预期复核状态、替换来源和跨段别名。该断言仅表示此次实现对这组已知合成回归项的行为符合标注，不能外推到案件材料、地域表达、OCR 噪声、未知实体类型或真实模型输出。

2026-09-08 在本工作区执行上述命令的合成快照为：11 个语料项、9 个标注实体出现、9 个观测实体出现、9 个精确匹配、0 个误报、0 个漏检；9/11 项自动就绪（`818181 ppm`），含实体项中 5/7 项自动就绪（`714285 ppm`），2/11 项待复核（`181818 ppm`）。实际自动输出由 2 个确定性规则实体、4 个已确认词典实体和 1 个本地 NER 加精确云佐证实体构成。这个快照仍只描述固定合成语料，不能作为真实案件准确率或 Provider 效果声明。

## 替换证据

每次实际替换都会在 `Analysis.replacements` 中记录 `finding_id`、原文 UTF-8 字节范围、输出 UTF-8 字节范围和别名；`source_sha256` 与 `output_sha256` 将这些范围绑定到原文和输出版本。`verify_analysis_source` 通过范围重建输出，逐条验证原文片段、别名和输出范围，未使用全文搜索猜测位置。`validate_analysis` 适合结果读取边界：它验证输出哈希、输出范围和残留检查；需要重新验证原文范围时，调用方必须同时提供加密原文给 `verify_analysis_source`。

别名的稳定令牌使用 `a` 到 `p` 编码 40 位哈希，不直接放入十六进制数字。这样独立残留扫描仍会阻断真正的长数字串，而不会因 namespace 变化时恰好生成连续十进制字符而把安全输出错误送入待复核。
