# 图示系统扩展与版本迁移

## 版本层次

- MCP envelope：整数 `schema_version: 1`，用于工具协议协商。
- DiagramSpec：字符串 `schema_version: "1.0"`，用于数据契约。
- 模板：语义版本 `1.0.0`，用于领域约束和布局行为。
- 渲染器：实现版本参与内容地址或制品元数据，避免静默复用不同字节。

这三类版本不能互相替代。读取器必须拒绝未知主版本；未知 minor 版本只有在显式声明兼容时才能接受。

## 兼容性规则

新增可选字段、枚举或关系仍可能使旧读取器失败，应发布新的 DiagramSpec minor 版本并进行能力协商。删除字段、改变关系方向、修改状态语义、改变必填性或重解释既有值属于主版本变更。模板只收紧约束时至少提升 minor；改变布局字节但不改变语义可提升 patch，并更新快照与渲染版本。

## 新增关系或节点类型

先证明现有注册表无法准确表达，再同步更新机器 Schema、Rust 枚举、关系方向表、模板白名单、文档、正反例和迁移器。不得先在 metadata 或 `related_to` 中暗藏长期私有语义。对称关系仍保存明确 source/target；方向性关系必须给出迁移映射。

## 新增模板

新模板使用唯一 ID 和语义版本，复用公共 DiagramSpec，并提供描述符、至少一个虚构样例、模板语义测试、渲染/安全快照、性能档位、WorkBuddy 选择规则和迁移说明。只改变视觉主题不构成新模板。

## v1 内迁移

迁移流程为“读取旧版本 → 结构映射 → 显式诊断 → 完整新版本校验 → 写入新制品”。迁移不能原地覆盖源制品；provenance 设置 `parent_spec_hash` 和 `change_summary`。

无法映射的事实状态设为 `unknown`；缺少来源时创建诊断而不是伪造来源；无法确认的法律版本保持未核验；旧关系方向不明确时停止自动迁移并要求人工选择。名称不是 ID，不能仅按相同 label 合并节点。

## 旧图模型适配

旧 Map/Graph 数据可作为兼容输入，但缺少来源、状态、法律版本和领域字段。适配器只映射能证明的节点、边、来源和布局提示：

- 未提供状态时使用 `unknown`。
- 无准确关系时允许产生一次 `related_to` warning，但不得批量静默降级。
- 无法定位的来源保留缺口诊断。
- 适配结果是新的 DiagramSpec，不反向写回旧权威数据。

## Patch 迁移

Patch 不是跨主版本迁移格式。升级 Schema 或模板后，应先迁移并完整验证基线，再以新 spec hash 接受新的 patch。旧 hash、旧字段路径或删除了的枚举必须拒绝；不得为了兼容而跳过引用和语义校验。

## 发布流程

1. 写变更提案与兼容性分类。
2. 同步 Schema、类型、关系/模板注册表和文档。
3. 提供旧→新迁移器、成功与失败 fixtures。
4. 跑双读/差分测试、安全快照和性能测试。
5. 先让客户端通过能力发现协商新版本，再逐步切换写入。
6. 保留旧读取期和回滚路径；旧写入停止日期必须明确。

## 第二阶段扩展方向

可评估固定版本 Dagre/ELK、SVG/PDF 导出、跨图索引和桌面工作台联动，但必须保持模型—渲染隔离、离线默认、来源闭合和正向批准链。任何外部布局引擎都应固定版本/选项，禁用网络，并用同一组样例做语义不变与视觉差分验收。
